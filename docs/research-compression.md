# 調査: 配信画像の圧縮方式(Day2 探索)

AVIF 連番(現行)に対し、動画コーデック(カラー/アルファ分離)が容量面で有利かを調べた記録。**緯線エッジ1本・PSNRのみ**の予備調査で、方式の決定ではない。決定は「7. 未検証」の実測後に DD として行う。

## 1. 問い

5,928枚(約475MB @AVIF q60 換算)を配るとき、動画コーデックにすれば小さくなるか。代償(ランダムアクセス、デコード)は許容できるか。

## 2. 方法

- 入力: Blender(Cycles)で撮った実レンダー。960×540、半透明(ガラス・霞)、細線、発光点を含む手作りシーン。緯線エッジ1本(30°、31枚)。
- 比較対象: AVIF 連番(Pillow、speed 6、q40/60/80、4:2:0/4:4:4)/ 動画: libaom-av1、libsvtav1、libx265、libvpx-vp9(speed 8、4:2:0、CRF 3段階)。動画はカラー(プリマルチプライド sRGB、BT.709 フル)とアルファ(グレー)を**別ストリーム**で符号化。
- GOP: 1 / 8 / 31(エッジ全体)。ランダムアクセスで必要なデコード枚数は (GOP+1)/2。
- 指標: アルファ PSNR、灰(128)・白(255)に合成した PSNR、デコード ms/枚。
- ツール: `python/tools/codec_bench.py`(結果を1通りごとにCSVへ書き、再実行で再開)、`python/tools/render_bench_edges.py`(テスト画像生成、4コアで76枚に約33分)。

## 3. 結果(緯線エッジ、画質約36 dB に揃えた比較)

KB/枚、AVIF q40(41KB・36.1 dB)を1.00とする。表の点間の目補間を含む概算。

| 方式 | GOP | 容量 | AVIF比 |
| --- | --- | --- | --- |
| AVIF | 1 | 41KB | 1.00 |
| AV1 (aom) | 1 | 48KB | 1.17 |
| AV1 (aom) | 8 | 23KB | 0.55 |
| AV1 (aom) | 31 | 19KB | 0.46 |
| AV1 (SVT) | 8 | 約25KB | 約0.60 |
| HEVC | 8 | 約27KB | 約0.65 |
| HEVC | 31 | 約24KB | 約0.58 |
| VP9 | 8 | 29KB | 0.70 |
| VP9 | 31 | 約24KB | 約0.58 |

約37.7 dB でも同傾向(AV1 aom GOP8: 35KB、AVIF 約62KB で 0.57)。生値(抜粋、灰合成 PSNR / KB):

| 方式 | GOP | 値 |
| --- | --- | --- |
| AVIF q40 / q60 / q80 (4:2:0) | 1 | 36.1 dB 41KB / 39.1 dB 81KB / 41.4 dB 119KB |
| AV1 aom CRF24 / 32 / 40 | 8 | 37.6 dB 36KB / 36.0 dB 23KB / 34.5 dB 14KB |
| AV1 aom CRF24 / 32 / 40 | 31 | 37.7 dB 31KB / 36.1 dB 19KB / 34.5 dB 11KB |
| HEVC CRF20 / 26 / 32 | 8 | 37.3 dB 39KB / 34.8 dB 20KB / 32.2 dB 9KB |

## 4. 分かったこと

1. GOP 1(1枚ずつ独立)では動画に利点がない。利点はフレーム間予測から来る。
2. GOP 8 で約半分、GOP 31 で約0.46〜0.58倍。8→31 の上積みは1割程度。
3. アルファ精度は動画のほうが高い傾向(CRF32・GOP8 で 39.6 dB vs AVIF q40 の 35.8 dB)。
4. 容量・画質ではコーデック間の差は小さい。選択はブラウザ対応とハードウェアデコードの有無で決まる(未調査)。
5. 動画の到達画質は灰合成 37〜38 dB 止まり(CRF 範囲内)。AVIF q60(39 dB)相当の比較は行っていない。
6. 換算: 5,928枚で AVIF q60 約475MB → 動画(GOP8)約240MB(ノード画像の共有は未考慮)。

## 5. 代償

- AVIF は1枚表示=1枚デコード(約14ms)。動画は1枚表示に平均 4.5枚(GOP8)〜16枚(GOP31)のデコードが必要。
- ffmpeg 別プロセスの実測(約20〜25ms/枚、カラー+アルファ2本込み)を掛けた上限目安は GOP8 で約100ms、GOP31 で約370ms。ブラウザの値ではない。
- 順方向の連続操作は1枚ずつなので軽い見込み。重くなるのは逆方向・ノード切替・ジャンプ。

## 6. 副産物: アルファ配信の不具合(DD34, DD44)

プリマルチプライド版 AVIF は Chromium 141 で半透明部が暗く描画された(合成 PSNR 25 dB。ストレート版は 44 dB)。AVIF のフラグも `createImageBitmap` の `premultiplyAlpha` も補正に使われない。パッカーを常にストレート出力に修正済み。**Android 実機は未確認。**

## 7. 未検証(次にやること)

- 経線(lon)・斜め(diag)エッジで同じ傾向か(`codec_bench.py --quick` で足りる)。
- 見た目の画質(PSNR は縁の質や時間的ちらつきを表さない)。
- WebCodecs `VideoDecoder` でのブラウザ側デコード速度、キーフレーム(ノード)設計、逆再生コスト。
- Android 実機(AVIF のストレート表示、動画デコード)。
- 画質を AVIF q60 水準まで揃えた比較(CRF 範囲を広げる)。
